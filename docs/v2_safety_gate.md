# AITC V2 Phase 8：确定性 Safety Gate

实施日期：2026-10-10。基线为 Phase 7 合入 main 后的 `afc6368`。

## 实际接线

Safety Gate 位于原全局协调之后、格式化和结果仓库之前。它只使用代码、当前批次固定的
静态配置快照和原策略 fallback，不调用模型。Qwen 或 DeepSeek Reviewer 的意见始终是
advisory，不能批准、跳过或修改安全检查。

```text
Baseline candidate
  → 原全局协调
  → Safety Gate
      → 合法：原方案或已有 phase_check 的上下界修正
      → 不合法：原单点候选 → 原时刻表 → 既有 [0] * 10 无动作标记
      → 每个 fallback 重新经过同一 Safety Gate
  → 原格式化 / 结果仓库 / TCP
```

Safety Gate 对整批路口使用一次深复制的静态配置快照，避免运行中配置替换导致同批路口
按不同版本判断。路口之间独立；一个路口失败不会改变其他路口。意外的程序错误继续传播，
结果仓库不会发布半批新结果。

## 已实施规则

- 最终方案必须是严格的十元素 `SignalPlan`：八个相位时长、一个保留位、一个方案号。
- 数值必须有限，布尔值和数值字符串不能冒充时间；相位时长不能为负。
- 保留位必须为 0，避免它被旧输出格式误当作第九个相位。
- 方案号必须是非负整数或纯数字字符串，不能静默截断小数。
- 第一个 0 是相位结束标记，之后不能再出现非零相位。
- 非空方案必须与已有路口/方案/相位静态规则一致。
- 已配置且最小值大于 0 的相位不能缺失。
- 已知上下界仍复用生产 `phase_check` 做确定性修正，修正结果必须再次通过 Safety Gate。
- 全零十元素沿用旧 selector 的“无动作”标记，状态为 `no_action`，不宣称它是安全配时。

现有静态配置尚未覆盖全部 186 个生产路口。冻结回放中有 42 个非空方案缺路口配置、
4 个缺当前方案规则，另有 2 个路口的活动相位缺边界，共 48 个方案只能得到部分覆盖。
按本阶段确认的兼容策略，这些方案保持原输出，并明确记录：

```json
{
  "safety_status": "partial",
  "safe": null,
  "missing_rules": ["intersection_config"]
}
```

`partial` 不等于安全通过。后续补齐真实静态规则后，才能将这些路口改为全面强制拦截。
每批次还会汇总记录一条缺规则告警，避免按路口重复刷屏。
本阶段没有代码依据可验证行人最小绿、冲突相位矩阵、黄灯/全红清空时间等规则，因此没有
虚构这些约束。它们需要可信的路口配置后再加入。

## Fallback

安全失败按以下顺序处理：

1. 使用全局协调前捕获的原单点 Baseline 候选；
2. 使用原工作日/周末时刻表当前小时方案；
3. 两者都无效时，使用既有 `[0] * 10` 无动作标记。

每个候选都会重新检查。完整规则覆盖时只有 `valid` fallback 能发送；规则缺失时按兼容策略
允许 `partial` fallback，但 `safe` 保持 `null` 并告警。结构错误和违反已知规则的 fallback
不会发送。

报告保留旧 `check_status`、`msg`、`modifications` 字段，并新增 `safety_status`、`safe`、
`issues`、`missing_rules`、`safety_modifications`、`fallback_source`、`fallback_reason`。
TCP 业务报文没有新增字段，配时结构和既有客户端协议保持不变。

## 验证

新增 27 项 Safety Gate 单元与集成测试，覆盖严格结构、非有限数值、相位连续性、保留位、
方案号、静态配置损坏、缺规则兼容、上下界修正、候选/时刻表/no-action fallback、配置快照、
路口隔离、输入不可变、结果仓库原子发布，以及真实两轮 186 路口黄金回放。

两轮回放中最终方案、旧报告字段、格式化 payload 和 TCP 字节与 Phase 7 冻结结果一致；
每轮报告为 134 个 `valid`、48 个 `partial`、4 个既有 `no_action`。

2026-10-10 验证结果：主测试 453 项、经验模块 118 项、控制函数 9 项、全局处理器 23 项
全部通过；compileall、pip check 和 git diff --check 通过。
