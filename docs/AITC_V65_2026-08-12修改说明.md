# AITC V65 修改说明（2026-08-12）

## 1. 修改背景

AITC V65 保留了 V2.63 的 `lib` 算法实现，但将原先集中在
`Server_AITC.py` 中的服务启动、数据接入、周期决策、结果广播等职责拆分到
`app/`、`infra/` 和 `runtime/`。

本次修改的目标是补齐重构后遗漏的 V2.63 运行能力、修复实际运行错误，并按
当前部署要求关闭不再使用的 Nacos 配置同步。

本文只记录最终保留的修改。曾尝试增加、随后已撤回的网页时间表兼容接口不在
本版本修改范围内。

## 2. 修改清单

### 2.1 恢复经验池定时任务的应用生命周期

修改文件：

- `runtime/application.py`
- `app/config.py`
- `test/test_application.py`
- `test/test_app_config.py`

修改内容：

- 在 `create_application()` 中创建 `ExperiencePoolScheduler`。
- 在 `AITCApplication.start()` 中启动经验池调度器。
- 在 `AITCApplication.stop()` 中停止经验池调度器。
- 增加配置项 `enable_experience_pool_scheduler`。
- 默认启用经验池调度，保持 V2.63 的运行逻辑。

配置开关：

```text
AITC_EXPERIENCE_POOL_ENABLED=true|false
```

默认值为 `true`。

经验池继续使用原有模块：

```text
lib/data_ANS/experience_runtime.py
lib/data_ANS/experience_pool.py
lib/data_ANS/experience_release.py
```

主要输出包括：

```text
lib/experience_pool/experience_pool_full.json
lib/experience_pool/new_wwx.json
lib/experience_pool/rolling_experience_table.json
lib/experience_pool/runs/<日期>.json
logs_data/experience_pool/daily/<日期>/
```

说明：旧路口仍通过 `cha1.py` 读取 `lib/wwx.json`；经验池维护的新经验表为
`lib/experience_pool/new_wwx.json`。当前两套经验表并行，后续按路口迁移。

### 2.2 恢复控制输入快照

修改文件：

- `runtime/decision_pipeline.py`
- `runtime/application.py`
- `app/config.py`
- `test/test_decision_pipeline.py`

修改内容：

- 在调用全局 `coordinate()` 前，可选保存本轮完整控制输入。
- 保留 V2.63 快照中的关键字段：
  - `coordinate_input`
  - `coordinate_map_set`
  - `online_map`
  - `overflow_map`
  - `extend_map`
- 使用临时文件和 `os.replace()` 原子写入，避免产生半写入 JSON。

配置：

```text
AITC_CONTROL_SNAPSHOT_ENABLED=false
AITC_CONTROL_SNAPSHOT_DIR=logs_data/control_snapshots
```

默认关闭。启用后输出：

```text
logs_data/control_snapshots/control_*.json
```

### 2.3 恢复固定决策周期语义

修改文件：

- `runtime/application.py`

V65 原先每轮决策完成后再等待完整间隔，实际周期为：

```text
决策耗时 + 50 秒
```

现改为与 V2.63 一致：记录本轮开始时间，决策完成后只等待剩余时间：

```text
max(0, 50 秒 - 本轮决策耗时)
```

因此 `AITC_DECISION_INTERVAL_SECONDS=50` 表示两轮开始时间之间约为 50 秒。

### 2.4 修复全局协调模块缺少 datetime 导入

修改文件：

- `lib/Global_intersection_coordinate.py`

问题表现：

```text
NameError: name 'datetime' is not defined
```

触发位置为绿波协调逻辑中的：

```python
datetime.fromtimestamp(...)
```

修复内容：

```python
from datetime import datetime
```

修复后，全局 `coordinate()` 进入相关绿波时间判断时不再中断整轮决策。

### 2.5 默认关闭 Nacos 配置同步

修改文件：

- `app/config.py`
- `runtime/application.py`
- `test/test_app_config.py`
- `test/test_application.py`

修改内容：

- `replay`、`development`、`production` 三种运行模式默认全部关闭 Nacos 同步。
- `AITCApplication` 的 `enable_config_sync` 默认值改为 `False`。
- 不配置环境变量时，不启动以下同步任务：
  - floating-value
  - intersection-result
  - road-state
  - time-schedule
- 本地 JSON 配置的读取和使用不受影响。

如后续需要重新开启，可显式设置：

```text
AITC_ENABLE_CONFIG_SYNC=true
```

## 3. 未修改但已确认的行为

### 3.1 TCP 客户端断开日志

V2.63 和 V65 都会：

1. 将连接 `65432` 的 socket 加入客户端列表；
2. 接收客户端上传的流量、排队、阶段、扩展等数据；
3. 向同一批连接广播控制结果；
4. 在发送失败后移除失效连接。

V65 的 `ResultSender` 会更集中地打印：

```text
客户端断开连接，已标记移除
```

该日志通常来自本地回放程序（例如 `client_tcp.py`）发送结束、重连或关闭旧
socket，不表示主控算法失败。本次未修改 TCP 协议和广播逻辑。

### 3.2 主控路线函数化

当前实时主控仍通过：

```text
runtime/decision_pipeline.py
  -> lib.DQN_Select.DQN_select
  -> lib.Global_intersection_coordinate.coordinate
  -> phase_check
```

`Global_intersection_coordinate.py` 已调用 `lib/control_functions/` 中拆分的
Internet、Mixed、Flow、特殊路口、最小周期和浮动值处理函数，因此主控路线
函数化模块仍在实际主流程中生效。

## 4. 已撤回、不属于本次最终版本的修改

曾计划在新 HTTP 服务中增加以下旧网页兼容接口：

```text
/road_state
/schedule
/update
/update_info
```

由于原网页暂时无法访问，无法确认实际请求契约，该次尝试已完整撤回。最终代码
中没有新增 `ScheduleService`，也没有新增上述路由。

## 6. 最终运行状态

本次修改完成后，V65 的最终行为为：

- 经验池调度默认启用；
- 新经验表模块继续维护 `new_wwx.json`；
- 控制快照能力已恢复，但默认关闭；
- 决策周期恢复为 V2.63 的固定周期语义；
- 全局协调中的 `datetime` 运行错误已修复；
- TCP 客户端断开时自动清理，不影响后续客户端重连和主控运行。
