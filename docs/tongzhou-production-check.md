# 通州路口排查版本运维回传说明

按原流程更新并启动，连续运行至少 20 分钟。取启动至少 10 分钟后的记录。
如需排查最小绿或手动调时，在已知问题路口操作一次，记下路口编号、方案号、修改时间及修改前后数值，再运行至少 10 分钟。

日常先按下方步骤生成一次性取证文件。需要逐条复盘时，再回传相应时段的三个文件。

| 文件 | 内容 |
| --- | --- |
| 版本目录下的 server.log | 包含启动、配置同步、完整配时决策和学习任务日志 |
| 当天的 YYYY-MM-DD_send.txt | 实际发送日志 |
| shadow/flow_time_allocator_YYYY-MM-DD.jsonl | 分配器诊断 |

后台运行的正式日志统一写到 server.log。启动命令生成的 AITC.log 保存直接写入终端的输出，
仅在缺少 server.log 或需要排查解释器、第三方库异常时查看。
诊断默认记录，无需额外开关。若正好覆盖早晚高峰，保留同版本该时段的上述日志。
请将操作时间与日志一起发回，以便核对配置是否生效及最终发送是否变化。

## 一次性取证

在已运行版本的目录里执行，替换路口和起止时间。时间按北京时间解释。
三批日常验收可先取【19组】1700542、【49组】2703802 和【28组】1700471。

```bash
python tools/check_online_learning.py --cross 1700542 --cross 2703802 --cross 1700471 \
  --start '2026-11-20 16:55' --end '2026-11-20 17:47' \
  --export aitc-evidence.json
```

回传 `aitc-evidence.json`，附三个路口的算法开启状态及同一时段的信号机实际执行记录。
用 `--log-dir 目录` 可读取运维回传的日志与日更清单，支持平铺存放。
如需另指定运行日志，可加 `--log 文件`。文件收到后可删除本次导出的 JSON。

导出的 `sent_program_counts` 和 `sent_release_counts` 按发送记录统计方案号和经验版本，
`latest_send` 列出最近一次的方案号和各阶段绿时。
`sent_batch_evidence` 按决策批次汇总候选、协调配时来源和回退，同一批次多次发送只计一次。
`changed_experience_candidate_batches` 记录已匹配发送的批次中，候选选用更新经验点的次数。
值为 `null` 时需要当前和上一版经验表才能核实，可在该次经验仍生效时从生产版本目录导出。
`source_pair` 反映当前日志目录可读取的原始 FLOW/EXTEND，过去的生产日更结果以日更清单为准。

## 19 组逐路口采用

默认走影子对照的 19 组路口，通过现场核对后可写入 `AITC_FLOW_ALLOCATOR_19_NEW_ROADS`，用逗号分隔。
重启后，候选总模式为 `new` 且路口在候选范围内时，指定路口才可能采用。移除编号后恢复影子对照。

在 `lib/plan_id_overrides.json` 明确登记的平台路口统一按登记方案、配置阶段和绿时边界配时。
候选采用继续受全局模式、路口范围和输入质量约束。
