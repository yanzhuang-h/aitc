# 19/49组排查版本：运维回传说明

按原流程更新并启动，连续运行至少20分钟。启动前10分钟用于形成运行窗口。
之后在一个已知问题路口按现有方式修改一次平台最小绿或手动增减秒数，继续运行至少10分钟。
请记下：路口编号、方案号、修改时间、修改前后数值。

日常先按下方步骤生成一次性取证文件。需要逐条复盘时，再回传相应时段的三个文件。

| 文件 | 内容 |
| --- | --- |
| 版本目录下的 server.log | 包含启动、配置同步、完整配时决策和学习任务日志 |
| 当天的 YYYY-MM-DD_send.txt | 实际发送日志 |
| shadow/flow_time_allocator_YYYY-MM-DD.jsonl | 分配器诊断 |

后台运行的正式日志统一写到 server.log。启动命令生成的 AITC.log 保存直接写入终端的输出，
仅在缺少 server.log 或需要排查解释器、第三方库异常时查看。
诊断默认记录，无需额外开关。若正好覆盖早晚高峰，保留同版本该时段的上述日志。
请将操作时间与日志一起发回，以便核对配置是否生效及最终发送是否变化。

## 一次性取证

在已运行版本的目录里执行，替换路口和起止时间。时间按北京时间解释。

```bash
python tools/check_online_learning.py --cross 1700124 --cross 1700452 \
  --start '2026-11-19 16:05' --end '2026-11-19 17:20' \
  --export aitc-evidence-1119.json
```

回传 `aitc-evidence-1119.json`。脚本只读现有日志和经验文件，可在日志副本上加
`--log-dir 目录` 运行。文件收到后可删除本次导出的 JSON。现场是否执行仍以信号机记录为准。

## 19 组逐路口采用

通过现场核对的 19 组路口可写入 `AITC_FLOW_ALLOCATOR_19_NEW_ROADS`，用逗号分隔。
重启后，候选总模式为 `new` 且路口在候选范围内时，指定路口才可能采用。
移除编号可恢复该路口原先的影子对照。已在采用范围的旧路口沿用原策略。
