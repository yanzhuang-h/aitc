## 2 数据底座开发

目标：将现有的数据收发、运行缓存、数据聚合、配置、经验池等能力逐步从 `Server_AITC.py` 和旧模块中剥离，沉淀到 `infra/data` 数据底座中。后续 Agent 或其他服务可以通过数据底座接口获取数据，例如千问主控大模型查询路口数据、调用 RAG、查询经验池等。

### 2.1 数据范围

- [ ] 路口车流数据：视频感知流量数据、排队数据、信号阶段数据。
- [ ] 雷达/博研数据：雷达普通数据、雷达事件、博研设备数据。
- [ ] 互联网/外部扩展数据：online、latest、extend。
- [ ] 溢出告警数据：overflow warning。
- [ ] 配置项：road_info、cross_info、road_state、intersection_result_config、floating_value。
- [ ] 经验池：DQN/算法生成的 EXP 数据。
- [ ] 时段方案：time_schedule、内外部时段表、每日更新结果。

### 2.5 扩展性要求

- [ ] 新增数据类型时，只需要扩展分类规则、缓存策略和处理适配。
- [ ] 新增数据来源时，优先扩展 receiver，不直接改算法。
- [ ] 新增接口时，优先通过数据底座暴露，不让 Agent 直接读取旧文件。
- [ ] 运行数据、缓存、日志、模型文件不提交到 Git。

数据底座最终应该专注做数据的接收、分类、缓存、持久化、聚合、查询和对外提供接口。Agent、算法和服务入口都应通过数据底座获取数据，而不是直接读写散落的旧文件。
