# 控制模型与抽象接口设计（2026-08-10）

## 1. 背景与目标

数据底座已开发完成。本周开始开发**控制模型与抽象接口**：把现有"全局模块"按职责拆分，互联网数据处理前置融入单点，控制逻辑收敛为"单点完备 + 多路口协同补强"，并由大模型 Agent 把各控制模块作为工具统一编排。

## 2. 架构重组决策

原"全局模块"实际混合了"互联网数据处理"与"多路口协调"两类职责。拆分原则：

- **互联网数据处理的本质是数据融合，不是方案控制**，因此前置到单点输入。
- 单点控制是完备的：单点方案生成后，多数路口可直接发送。
- 只有部分路口需要**多路口协同**（绿波、应急），按需接入。
- 方案生成独立化，放在协同前面；协同只做相位/时间的大幅调整。

### 2.1 模块划分

```
智慧交通数据底座（已有）
  车辆数据 / 排队数据 / 互联数据 / 路口状态数据 ...
  经验池（迭代）/ 配置项 / 应急方案库
  互联网数据融合（前置）

智慧交通控制模块（本轮建设）
├─ 路口控制方案生成模块（单点）
│   ├─ 路口详细状态生成：把融合数据整理为路口级状态
│   └─ 路口方案生成：由状态生成相位/绿灯方案
├─ 全局路口调度判断：判断该路口是否需要多路口协同
├─ 多目标协同控制模块
│   ├─ 绿波模块：多路口成组协调
│   └─ 应急控制模块
│       ├─ 主动疏堵
│       └─ 路口溢出处理
├─ 路口运行状态判断 / 异常处理模块（输入全部数据但处理不了的降级）
├─ 路口安全引擎：最终安全校验（绿灯上下限/行人/冲突/周期）
├─ 输出控制 → 信控平台
```

### 2.2 数据流

```
数据底座 → 互联网数据融合
  → 路口详细状态生成（单点输入 = 本地感知 + 互联网融合 + 视频感知补充）
  → 路口方案生成（单点结果）
  → 全局路口调度判断
      ├─ 无需协同 → 安全引擎 → 输出控制 → 信控平台
      ├─ 绿波需求（如 123 路口成组）→ 绿波模块（单点结果一起处理一起发）→ 安全引擎 → 输出
      └─ 应急需求（拥塞路口 + 上下游 4 路口）→ 应急控制 → 安全引擎 → 输出
```

## 3. 接口设计（app/core/control/）

```text
app/core/control/
├─ interfaces/            抽象接口（Protocol，所有模块依赖接口不依赖实现）
│   ├─ data_source.py     数据输入抽象（路口级状态/原始数据）
│   ├─ single_point.py    单点方案生成抽象
│   ├─ synergy.py         多路口协同抽象（绿波/应急）
│   ├─ safety.py          安全引擎抽象
│   └─ dispatch.py        输出控制抽象
├─ single_point/
│   ├─ detail_state.py    路口详细状态生成
│   └─ plan_generator.py  路口方案生成（先包装 lib.DQN_Select）
├─ synergy/
│   ├─ green_wave.py      绿波模块
│   └─ emergency.py       应急控制（主动疏堵 / 溢出处理）
├─ dispatch/
│   └─ scheduler.py       全局路口调度判断（哪些路口需要协同）
├─ anomaly/
│   └─ detector.py        异常处理（数据异常降级）
├─ safety_engine.py       路口安全引擎
└─ output/
    └─ dispatcher.py      输出控制（协议打包 → 信控平台）
```

## 4. 与现有代码的对应

| 目标模块 | 现有实现 | 处理方式 |
| --- | --- | --- |
| 路口方案生成 | `runtime/decision_pipeline.py::_process_single_intersection` → `lib.DQN_Select.DQN_select` | 包装现有 DQN，静默导入，不动 `lib/` |
| 全局路口调度判断 | `PeriodicDecisionPipeline.run_once` 中全量调用 `coordinate` | 拆为"判断是否协同" + 按需调用绿波/应急 |
| 安全引擎 | `phase_check`（相位校验） | 保留并包装为安全引擎 |
| 输出控制 | `runtime/result_formatter.py::format_result` | 包装为输出控制 |
| 工具注册 | `agent/tools.py::_TOOL_SCHEMAS` + `agent/qwen_agent.py::_ACTION_TO_TOOL` | 升级为统一 `ToolRegistry` |
